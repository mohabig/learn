Deployed means a stranger can run it

Four things change the moment the URL is public, and none of them are about your code.

Configuration moves to the host's secret store, not a file in the repo.

A public endpoint needs a spend ceiling and a rate limit before it needs anything else. An open, unmetered endpoint sitting in front of a paid API is a bill waiting to happen, and it takes one bored visitor overnight.

Cold starts on free tiers add seconds to the first request after an idle period, which will look exactly like a slow model until you go and check.

And the platform's proxy may buffer your stream, turning Day 5's work into an ordinary slow response. You can only see that from outside your own network.

So: deployed means a stranger can run it, and a stranger includes the one who wants your key.

The README is the deliverable

Six sections, and you can write them in an hour. What it does, in one paragraph a non-expert understands. An architecture diagram — a Mermaid block is fine. Cost per request, with the arithmetic shown. p50 and p95 latency, and how you measured them. Known failure modes, and what you'd fix with another week. A live link.

A short note helps another person understand what your program does, what examples you tried, and what you might improve next.

"Uses AI" is not evidence. "$0.004 per request, p95 2.4 seconds, 31 percent cache hit rate, and here's why I chose the small model first" is.

So: the numbers you collected all week are the deliverable, and the README is just where they live.

The build, step by step

  1. Audit for secrets before anything else. Search the repo and the git history for key-shaped strings. If one was ever committed, rotate the key — removing the line does not help.
  2. Add the public-endpoint essentials: a health route, a request id on every response and log line, a per-request token ceiling, and a simple per-address rate limit.
  3. Deploy to whatever platform gets you live in under 20 minutes — Render, Fly.io, Railway, Vercel. Put the API key in the host's secret store and set a billing alert on your provider account today, not later.
  4. Hit the live URL from a different network — phone tethering works. Record time to first token and total time from there. Localhost numbers are fiction.
  5. Run Day 2's 20-case file against the deployed endpoint. Record cost per request and p50/p95, cached and uncached, from real responses.
  6. Break the live one: a bad key, an input far past your window, an empty body. Confirm each returns a clean message with a request id, as Day 6 promised.
  7. Write the README's six sections and paste the real table. Add the architecture diagram and a one-line install-and-run.
  8. Save your work and write down one thing you learned. Keep the project private unless a trusted adult has reviewed and agreed to sharing it.

Where people get stuck

  • A key in git history. Rotation is the only fix, and it's a five-minute job that turns into an hour if you find out later.
  • A buffering proxy in front of the stream. Invisible on localhost, obvious from your phone.
  • A README full of setup instructions and no numbers. The numbers are the entire point of Week 1.
  • Skipping the half day off. Burnout on Day 19 costs far more than a Sunday afternoon does.
